Python is one of the most popular languages in the world — and one of the friendliest for beginners. Everything you planned in flowcharts (sequence, selection) now becomes real, typed code.

<Definition term="Variable">
  A named box that stores a value your program can use and change later.
</Definition>

## Key ideas

### Output and storage

`print()` shows something on screen. A variable stores something for later with `=`:

<CodeBlock lang="Python">
print("Hello, world!")
score = 0
print(score)
</CodeBlock>

This prints `Hello, world!`, stores 0 in `score`, then prints `0`. Text in quotes is called a **string**; numbers need no quotes.

### Input — with a catch

`input()` asks the user to type something. The catch: whatever is typed always comes back as a **string** — even digits. To do maths with it, convert it first:

<CodeBlock lang="Python">
colour = input("Enter a colour")
print(colour)
</CodeBlock>

Type "blue" and it prints blue. Now with numbers:

<CodeBlock lang="Python">
age_text = input("Your age: ")
age = int(age_text)
next_year = age + 1
print(next_year)
</CodeBlock>

`int()` turns the text "12" into the number 12. Without it, `age + 1` would crash — you cannot add 1 to text.

### Data types: four kinds of value

Every value in Python has a type, and the type decides what you can do with it:

- **Integer** — a whole number: 120, 0, -7.
- **Real** (float) — a number with a decimal part: 21.3, 1.609.
- **Character** — a single character: '!', 'V', 'o'.
- **String** — one or more characters: "house", "Victoria Ellis".

An Integer is a whole number; a Real can have a decimal part. A Character is only one character; a String is one or more. Mixing them up is a classic source of bugs — "10" (string) and 10 (integer) look alike but behave differently.

### Naming rules: valid and invalid identifiers

Variable names (identifiers) have strict rules:

- Valid: colour, totalCost, numA, result
- Invalid — starts with a number: 2ndPlace
- Invalid — has a space or full stop: my score, my.score
- Invalid — it is a reserved word: print, if
- Invalid — has a hyphen: my-score

Break a rule and Python refuses the name. Good names are also meaningful: totalCost beats x when someone else reads your code.

### Selection in code: if-statements

Remember the flowchart diamond? In Python it looks like this:

<CodeBlock lang="Python">
score = 65
if score >= 50:
    print("Pass")
else:
    print("Fail")
</CodeBlock>

The condition uses `==` for "is equal to" (a single `=` would try to store, not compare). The indented lines underneath run only when the condition is true. Indentation is not decoration in Python — it is part of the syntax.

<WorkedExample title="Trace the age checker">
  Code: `age = int(input("Age: "))` then `if age >= 13: print("Teen")` else `print("Child")`. The user types 10.

  Line by line: input shows "Age: " and the user types 10 — as text "10". int() converts it to the number 10, stored in age. The condition `10 >= 13` is false, so the indented print("Teen") is skipped; the else branch runs instead.

  **Answer:** The program prints "Child". If the user had typed 15, the condition would be true and it would print "Teen".
</WorkedExample>

<WorkedExample title="Read a division program">
  This program takes two numbers as input from the user, divides the first by the second, and outputs the answer:

<CodeBlock lang="Python">
num1 = int(input("First number: "))
num2 = int(input("Second number: "))
answer = num1 / num2
print(answer)
</CodeBlock>

  Trace with 20 and 4: num1 = 20, num2 = 4, answer = 20 / 4 = 5.0, prints 5.0.

  **Answer:** It prints 5.0 — and notice the Real result: division in Python gives a decimal even for whole numbers.
</WorkedExample>

<ImportantNote title="Common mistakes">
  - **= instead of ==** Correction: = stores a value (score = 65); == compares (if score == 65:). Using = inside an if is an error.
  - **Forgetting int() on input** Correction: input() always returns a string — wrap it in int() before any arithmetic, or the program crashes.
  - **Wrong indentation** Correction: the lines under if must be indented (usually 4 spaces). Python uses indentation to decide which lines belong to the if.
</ImportantNote>

## Practice

<PracticeQuestions>
  <PracticeItem question="What does this print? Line 1: x = 7. Line 2: print(x * 3)" hint="x stores the number 7.">
    21 — x holds 7, and 7 * 3 is 21.
  </PracticeItem>
  <PracticeItem question="The user types 9 for this code: n = int(input('Number: ')) then print(n + 1). What prints?" hint="int() converts the typed text to a number.">
    10 — "9" becomes the number 9, plus 1 is 10.
  </PracticeItem>
  <PracticeItem question="Fix the bug: if password = 'secret': print('Welcome')">
    if password == 'secret': — comparing needs ==; a single = tries to store and is an error here.
  </PracticeItem>
  <PracticeItem question="What is a string? Give an example from this lesson.">
    Text in quotes, such as "Hello, world!" or the result of input() before conversion.
  </PracticeItem>
  <PracticeItem question="Which of these identifiers is valid: totalCost, 2ndPlace, my score, my-score, print? Explain each.">
    totalCost is valid. 2ndPlace starts with a number — invalid. "my score" has a space — invalid. my-score has a hyphen — invalid. print is a reserved word — invalid.
  </PracticeItem>
  <PracticeItem question="Is 21.3 an Integer, Real, Character or String? What about '!'?">
    21.3 is a Real (it has a decimal part). '!' is a Character (a single character).
  </PracticeItem>
  <PracticeItem question="Why does this line crash: age = input('Age: ') then print(age + 1)?">
    input() returns a string, so age + 1 tries to add a number to text — you need int(input('Age: ')) first.
  </PracticeItem>
</PracticeQuestions>
