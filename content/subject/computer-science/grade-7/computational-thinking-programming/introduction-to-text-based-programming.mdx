So far you have planned with flowcharts and (maybe) built programs from snap-together blocks. Now it is time to meet code as professionals write it: typed text.

<Definition term="Programming language">
  An agreed way of writing instructions that a computer can follow, such as Python, Java or C++.
</Definition>

## Key ideas

### From blocks to text

Block languages let you snap commands together like puzzle pieces — you cannot make a syntax error because the pieces only fit where they belong. Text languages give you the same ideas (sequence, selection, repetition) but you type every character yourself. More freedom, more responsibility: the computer will not guess what you meant.

### What a language actually is

A programming language sits between human ideas and the machine. High-level languages like Python read almost like English, which makes them good for learning. Underneath, everything is translated into **machine code** — the 1s and 0s the processor actually executes. You write for humans; the translator handles the machine.

### Syntax: the grammar of code

Every language has strict rules called **syntax** — its grammar and spelling. The computer is completely literal: it does exactly what you typed, not what you meant.

<CodeBlock lang="Python">
print("Hello")
Print("Hello")
print("Hello"
</CodeBlock>

Line 1 is correct. Line 2 fails — Python keywords are lowercase, so `Print` means nothing. Line 3 fails — the closing bracket is missing. One character can be the difference between working and broken.

**Key term — syntax:** The exact spelling, punctuation and layout rules of a programming language. Break them and you get a syntax error.

<WorkedExample title="Read a line of code">
  Line: `name = input("Your name: ")`

  Reading left to right: `name` is a variable — a named box to store something. `=` stores a value into it (it does not mean "equals" here). `input(...)` is a command that shows the text in brackets on screen and waits for the user to type. So the whole line means: "show 'Your name: ', wait for typing, and store what was typed in the box called name."

  **Answer:** The line asks the user for their name and stores the answer in a variable called name.
</WorkedExample>

<ImportantNote title="Common mistakes">
  - **Wrong capitalisation** Correction: most languages are case-sensitive — print works, Print does not. Copy keywords exactly.
  - **Unbalanced brackets or quotes** Correction: every opening bracket needs a closing one, and every opening quote needs a closing one — count them when something breaks.
  - **Assuming the computer understands intent** Correction: it does not. "Print hello" without quotes and brackets is just words to Python — write the full, exact instruction.
</ImportantNote>

## Practice

<PracticeQuestions>
  <PracticeItem question="What is the difference between a block language and a text-based language?">
    Block languages snap visual pieces together (no syntax errors possible); text-based languages are typed by hand, giving more power but demanding exact syntax.
  </PracticeItem>
  <PracticeItem question="What is machine code?">
    The 1s and 0s a processor actually executes — everything written in a high-level language is translated into it.
  </PracticeItem>
  <PracticeItem question="Spot the syntax error: print('Total:' total)">
    A missing comma or plus between 'Total:' and total — two things next to each other with nothing joining them is not valid syntax.
  </PracticeItem>
  <PracticeItem question="In the line score = 10, does = mean 'equals'?">
    No — here = stores the value 10 into the variable score. "Equals" in a comparison uses == (coming up in Python).
  </PracticeItem>
</PracticeQuestions>
