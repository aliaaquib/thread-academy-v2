Every spreadsheet model and database is only as good as the data put into it — "garbage in, garbage out". Collecting data properly, and checking it on the way in, is a skill in its own right.

<Definition term="Data collection">
  Gathering information from the world in a planned way so it can be stored, analysed and trusted.
</Definition>

## Key ideas

### Methods: choose the right tool

- **Questionnaires / surveys** — many people, same questions. Cheap and fast; risk: people misunderstand or skip questions.
- **Interviews** — deeper answers from fewer people; slow and harder to compare.
- **Observation** — watching and counting (e.g. traffic at a junction); no opinions, just facts.
- **Sensors** — automatic measurement (temperature, light, motion); accurate and continuous, but need equipment.

Match the method to the question: counting cars needs observation or a sensor, not a survey about feelings.

### Validation: catch bad data at the door

**Validation** is automatic checking *as data is entered* — the computer rejects what cannot be right:

- **Presence check** — the field cannot be left empty (a nameless record is useless).
- **Type check** — numbers only in the Age field; "twelve" is rejected.
- **Range check** — Age must be 0–120; 250 is rejected.
- **Length check** — a phone number must be exactly 11 digits.

Validation does not prove data is *true* — 25 passes a range check even if the person is 40 — but it kills the obvious nonsense.

### Verification: check it was copied right

**Verification** confirms data was entered *accurately* — different job from validation:

- **Double entry** — type it twice; the computer complains if the two copies differ.
- **Proofreading** — a human reads the entered data against the original.

Validation asks "could this be right?"; verification asks "was this copied correctly?".

<WorkedExample title="Design the collection">
  The school wants to know how pupils travel to school. Method: a short questionnaire to every form — same questions, easy to count, one morning's work.

  The "Age" field gets a range check (5–19) and a type check (numbers only); "Name" gets a presence check. Two pupils type each form's answers (double entry) to catch typos.

  **Answer:** Questionnaire for the method; validation (range, type, presence) to block bad data; verification (double entry) to catch copying mistakes. Each technique guards a different failure.
</WorkedExample>

<ImportantNote title="Common mistakes">
  - **Confusing validation and verification** Correction: validation = automatic "could this be right?" checks on entry; verification = "was it copied correctly?" checks afterwards.
  - **Wrong method for the question** Correction: opinions need surveys; measurements need sensors or observation — match method to data type.
  - **Trusting validated data completely** Correction: validation blocks nonsense, not lies — "25" passes every check even when untrue.
</ImportantNote>

## Practice

<PracticeQuestions>
  <PracticeItem question="Which validation check rejects an empty 'Email' field?">
    A presence check — the field must contain something.
  </PracticeItem>
  <PracticeItem question="A temperature sensor records −300°C. Which check should have caught it, and why is the reading impossible?">
    A range check (e.g. −50 to 60°C) — and −300°C is below absolute zero, colder than physically possible.
  </PracticeItem>
  <PracticeItem question="Is typing a form twice an example of validation or verification?">
    Verification — it checks the data was copied accurately, not whether the values are sensible.
  </PracticeItem>
  <PracticeItem question="You need to know the busiest hour in the canteen. Which collection method fits best?">
    Observation (counting people per hour) or a sensor/counter — you need measured facts, not opinions.
  </PracticeItem>
</PracticeQuestions>

<Summary>
  - Data collection: gathering information in a planned way — surveys, interviews, observation, sensors.
  - Validation = automatic "could this be right?" checks on entry (presence, type, range, length).
  - Verification = "was it copied correctly?" checks (double entry, proofreading).
  - Watch out for: mixing up validation and verification, wrong method for the question, and trusting validated data blindly.
</Summary>
