</Definition>

## Ключевые идеи

### SQL описывает что, а не как

Вы пишете SELECT Name FROM Students WHERE Year = 12, а база данных сама разбирается, как найти строки, — SQL декларативен. WHERE фильтрует строки, ORDER BY сортирует их, а JOIN объединяет таблицы по их ключам. Поскольку вы описываете нужный результат, один и тот же запрос работает и на десяти строках, и на десяти миллионах.

### Ключи не дают данным потеряться

Первичный ключ гарантирует, что каждую строку можно найти ровно один раз — без него двух клиентов по фамилии «Смит» станет невозможно различить. Внешние ключи затем связывают таблицы: строка заказа хранит ID клиента, а не копирует весь его адрес, поэтому изменение адреса обновляется только в одном месте. Это основа надёжных данных.

**Термин — запрос:** Вопрос к базе данных на SQL — самый известный это оператор SELECT, извлекающий подходящие строки.

<WorkedExample title="Разобранный пример: запросы SELECT">
  Таблица Students имеет столбцы ID, Name, Year и строки (1, Priya, 12), (2, Tom, 11), (3, Aisha, 12), (4, Leo, 10). Напишите запрос, выводящий имена учеников 12-го класса в алфавитном порядке.

  Нужны только имена, из таблицы Students: SELECT Name FROM Students.
  Оставляем только строки 12-го класса: добавляем WHERE Year = 12. Подходят Priya и Aisha.
  Сортируем по алфавиту: добавляем ORDER BY Name. Aisha идёт раньше Priya.
  Полный запрос: SELECT Name FROM Students WHERE Year = 12 ORDER BY Name;.

  **Ответ:** Запрос возвращает две строки: сначала Aisha, затем Priya.
</WorkedExample>

<ImportantNote title="Типичные ошибки">
  - **Забытый WHERE в UPDATE или DELETE** Исправление: UPDATE Students SET Year = 13 без WHERE изменит каждую строку — всегда сначала пишите WHERE или проверьте его SELECT-запросом с тем же условием.
  - **Хранение одного и того же факта в двух таблицах** Исправление: храните его один раз и связывайте внешним ключом — дублированные данные расходятся, когда обновляется только одна копия.
</ImportantNote>
