Хорошие решатели задач не воспринимают каждую задачу как совершенно новую. Они ищут то, что уже видели, — и хорошие программисты делают то же самое со своими блок-схемами.

<Definition term="Распознавание закономерностей">
  Замечание повторения или сходства в задаче, чтобы переиспользовать одно решение вместо изобретения множества.
</Definition>

## Ключевые идеи

### Увидь повторение

Представь блок-схему, которая трижды печатает приглашение на вечеринку — по разу для каждого гостя. Шаги «вывести имя, вывести дату, вывести место» встречаются снова и снова. Это повторение — закономерность, а закономерности — подсказка: этому куску шагов нужно собственное имя.

### Подпрограммы: назови и переиспользуй

**Подпрограмма** — именованный кусок шагов, выполняющий одну работу. Главная блок-схема *вызывает* её везде, где нужно, специальным символом: прямоугольником с двойными вертикальными линиями (символ предопределённого процесса). Когда подпрограмма заканчивается, поток возвращается туда, откуда её вызвали.

### Подпрограммы могут принимать входные данные

Подпрограмма может принимать значение при каждом вызове — оно называется **параметр**. `greet(name)` выводит «Привет, » и то имя, которое ей передали: greet("Asha") выводит «Привет, Asha», greet("Omar") выводит «Привет, Omar». Те же шаги — разный результат.

### Зачем это нужно? Три причины

1. **Экономия времени** — напиши шаги один раз вместо копирования их пять раз.
2. **Тестируй один раз** — подпрограмму достаточно протестировать один раз; каждый вызов переиспользует шаги, которые уже точно работают.
3. **Исправляй один раз** — ошибка, исправленная внутри подпрограммы, исправлена везде, где она вызывается.

### Реальный пример: addNumbers

<CodeBlock lang="Шаги блок-схемы">
SUB-ROUTINE addNumbers: START → INPUT num1 → INPUT num2 → total = num1 + num2 → OUTPUT total → RETURN
MAIN: START → ... → CALL addNumbers → ... → CALL addNumbers → ... → STOP
</CodeBlock>

У подпрограммы есть **идентификатор** — её имя, addNumbers. Главный алгоритм вызывает её по этому имени везде, где нужна сумма, а затем продолжает с того места, где остановился. Логику сложения ты рисуешь один раз, тестируешь один раз и вызываешь сколько угодно.

### Подпрограммы могут принимать входные данные

<WorkedExample title="Проследи вызовы">
  Главный поток: НАЧАЛО → вызвать print_invite → вызвать print_invite → КОНЕЦ. Подпрограмма print_invite выводит одно приглашение и возвращается.

  Трассировка: НАЧАЛО, вызов print_invite (прыгаем внутрь, выводим приглашение, ВОЗВРАТ в главный поток), снова вызов print_invite (выводим приглашение, ВОЗВРАТ), КОНЕЦ.

  **Ответ:** Выведено два приглашения, хотя шаги написаны только один раз. Добавить третьего гостя — значит добавить один вызов, а не переписывать шаги.
</WorkedExample>

<ImportantNote title="Типичные ошибки">
  - **Копирование шагов вместо вызова** Исправление: вставить те же шаги трижды — значит исправлять ошибку трижды — вызывай подпрограмму вместо этого.
  - **Невнятное имя** Исправление: называй подпрограмму по её работе — print_invite, а не thing1 — тогда главный поток читается как инструкция.
  - **Забывают, что она должна закончиться** Исправление: подпрограмма завершается командой ВОЗВРАТ (назад к вызывавшему), а не КОНЕЦ — КОНЕЦ завершил бы всю программу.
</ImportantNote>

## Практика

<PracticeQuestions>
  <PracticeItem question="Какой символ блок-схемы вызывает подпрограмму?">
    Символ предопределённого процесса: прямоугольник с двойными вертикальными линиями слева и справа.
  </PracticeItem>
  <PracticeItem question="Блок-схема печатает рамку из звёздочек в 5 строк, затем заголовок, затем рамку снова. Где закономерность?">
    Шаги печати рамки повторяются — этот повторяющийся кусок и есть закономерность, и из него должна получиться подпрограмма, вызываемая дважды.
  </PracticeItem>
  <PracticeItem question="Что такое параметр, одним предложением?" hint="Подумай о greet(name), вызванной с разными именами.">
    Значение, переданное в подпрограмму при её вызове, чтобы те же шаги могли работать с разными данными.
  </PracticeItem>
  <PracticeItem question="Куда переходит поток после завершения подпрограммы?">
    Обратно в главный поток, на шаг сразу после вызова, — именно это и означает ВОЗВРАТ.
  </PracticeItem>
</PracticeQuestions>

<Summary>
  - Распознавание закономерностей: замечать повторение или сходство, чтобы переиспользовать одно решение вместо изобретения множества.
  - Подпрограмма: именованный кусок шагов, выполняющий одну работу, вызываемый из главного потока символом прямоугольника с двойными линиями.
  - Параметры позволяют одной подпрограмме работать с разными данными при каждом вызове.
  - Остерегайся: копирования шагов вместо вызова, невнятных имён и завершения подпрограммы командой КОНЕЦ вместо ВОЗВРАТ.
</Summary>
